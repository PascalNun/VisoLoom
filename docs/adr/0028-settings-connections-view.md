# ADR 0028 — Settings connections view

Status: Owner decision on 2026-11-21 ("both, in that order": connections view first, personal preset editor next). It replaces the four stacked provider forms in Settings with the saved-connections presentation the [information architecture](../ux/information-architecture.md) already accepts, without changing one byte of provider behavior: the same `ConnectionSettings` persistence, credential origins, check endpoints, timeouts and honest status strings.

## Decision

The Connections tab becomes a real connections view. A single native list shows every destination VisoLoom can render with — this computer, OpenAI, Google, xAI, BFL — each with its current state and, when it cannot render, the reason: `OpenAI — connected · 3 models`, `Google — missing API key`, `BFL — connected · rendering off`. Selecting an entry shows that connection's details: friendly name, destination, connection status, supported models, the API-key field, its allow/remember (and for OpenAI, scene-names) toggles, the per-provider data-sharing and billing disclosure, and the explicit **Check and save connection** / **Disconnect and forget key** actions. **Add connection…** is now one chooser for all destinations instead of four always-visible forms; every destination stays listed even when not set up, because an entry with a reason is exactly what the architecture asks for. The list refreshes live from the same `ConnectionSettings.Changed` and coordinator events that already drove the panel, so a check run from the settings dialog updates the panel menu and the list together.

The motivating defect: the Models tab's "Set up *" buttons all opened the Connections tab and focused **OpenAI's** key field — "Set up Google…" landed on OpenAI. The handoff now carries the provider it names and lands on that provider's row and key field; the native settings check's focus probe follows the OpenAI box to the view that owns it.

One saved connection per provider is the implemented scope; the friendly name is the provider's own, and multiple saved connections, renaming, office servers and their address fields remain targets — the wireframe mock for that state is unchanged. Because the four provider forms had degenerated into four near-identical copies, the view describes each provider once as data (`CloudConnection`: names, origins, hint and disclosure rows, tested/curated labels, and delegates to the existing `ConnectionSettings` configure/disconnect and adapter discovery methods) and runs one shared check flow over it. A fifth cloud provider extends that record, not the form count. The check flow keeps every existing behavior: the 15-second bound, busy-disable of the whole form, provider-native error mapping, the store-unavailable messages, model publication to the account lists, and the BFL rendering-off language — including its summary line, which says "rendering off" while the reference-upload decision stays open.

## Consequences

- Connections are inspectable at a glance: state and reason sit in one list instead of four scroll-past forms, and the supported-models disclosure names the same rows the Model menu offers, with the same provenance words (tested, curated, cloud, latest).
- Data-driven live summaries are honest by construction: `missing API key` requires allowed-but-keyless, `disabled` means allowed-off-with-a-key, `not set up` means no key — no state is invented.
- The remember/allow toggles re-read the persisted truth after every successful check or disconnect; previously only the OpenAI remember toggle synced (and only on reopen).
- The local row keeps its enable/check/setup block with live status from the coordinator rather than a construction-time snapshot.
- Native checks to re-run in Rhino: the settings walkthrough (pages, 360 pt narrow, no horizontal overflow, OpenAI key focus after "Set up OpenAI…", preferences unchanged) now exercises the view — the SettingsCheck reflection walks to the OpenAI key through `ConnectionsView`. The new focus-into-a-just-swapped-panel path is the one thing the old design never did; if the host refuses focus until a layout pass, the check will say so and this gets revisited. Windows paths remain, as with every Rhino UI change.
- No provider request, credential, or persistence key changed: `current-capabilities.md` and the model-selection plan are untouched; this is a Settings-layer reorganization, recorded here and in the phase-4 review only.
